CI compiler cache
=================

The native build workflow uses sccache v0.16.0 with GitHub Actions cache storage
for C and C++ compilation on Windows. The setup action is pinned to
the commit behind v0.0.11. Local CMake presets retain their normal compilers.

Only compiler results are cached. Configure, shader generation, linking,
packaging and every existing validation step still execute normally. The setup
action reports cache statistics in its post-run step. Compare compiler cache
hits and compile-step durations across subsequent runs before claiming a
speedup; the initial run may have no reusable entries.

The cache integration passed actionlint 1.7.12 (shellcheck and pyflakes disabled)
and git diff --check locally. Hosted Windows cache reuse is confirmed below; controlled cold/warm build-time
comparisons remain open. A passing cached build does not replace
Metal or D3D11 hardware validation.

macOS uses direct compilation. Run 38329721926 with caching enabled failed in
bgfx renderer_vk.cpp and renderer_webgpu.cpp: the compile commands contain
-ObjC++, but Clang reports that flag unused and rejects Objective-C declarations
in Cocoa headers. This is a cache-path incompatibility; the uncached build path
is retained pending a separately verified solution. No dependency sources or
compiler language flags are changed to work around it.

Upstream setup and cache documentation:
https://github.com/Mozilla-Actions/sccache-action/tree/v0.0.11
https://github.com/mozilla/sccache/blob/v0.16.0/docs/GHA.md

Observed hosted cache reuse
Windows run38330433954 reports GitHub cache hits in both workgroup jobs (70.70%
of cacheable calls for128; 50.50% for256). Compiler, CPU and shader steps pass.
The runtime sphere gate still fails independently. These hit rates establish
cache reuse, not a controlled build-time speedup. See
tests/results/ci-38330433954-sphere-reentry.txt for logs and source identity.
