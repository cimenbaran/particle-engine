GPU CAPABILITY REPORT

Write the device's advertised capability report and exit:

./out/macos-release/ParticleWorld.app/Contents/MacOS/ParticleWorld \
  --capabilities out/device.json

Add --no-indirect to report the selected fixed-capacity fallback. Capability
mode creates the native window and initializes the platform backend, but does
not create the particle scene or run GPU execution tests. It cannot combine
with GPU-test, benchmark, soak, frame-count or warmup modes. Exit is 0 when
required advertised capabilities are present, including a degraded fallback;
missing required capabilities or report-write failures exit 1. Backend/window
initialization failure is reported to the console before JSON can be produced.

The version-1 JSON contains supported/degraded/unavailable status, can_run,
individual checks with actual/required values and actionable failure reasons,
GPU IDs, backend, selected draw path and coordinate conventions. Normal app
startup applies the same required checks before running its GPU test suite.

Required: compute, six compute bindings, two vec4 instance-data slots, 32-bit
index buffers, image read/write, RGBA32U image writes and view IDs through 20.
Indirect draws are optional: unsupported or explicitly disabled uses masked
fixed-capacity instancing. No synchronous count readback is introduced.

The pinned bgfx API has no separate compute-buffer read/write or workgroup-
size capability query. The report explicitly states those limits: packaged
bulk shaders support 128 or 256 threads, selected at build time through
PW_WORKGROUP_SIZE (default 128). Single-thread control/export passes remain
one thread. Reports state the compiled bulk size, not a queried hardware limit.
Startup GPU tests validate actual shader execution, read/write buffer access,
image export, blits, readback, particle ABI, pool ownership and visibility.
An advertised-capability report alone does not prove execution support,
resource allocation success, benchmark compatibility or performance.

The coordinate convention is right-handed, Y-up, metres. NDC depth and texture
origin come from the selected backend rather than platform assumptions.

Configure the alternate variant with:
cmake --preset macos-release -DPW_WORKGROUP_SIZE=256
cmake --build --preset macos-release
ctest --preset macos-release
./build/macos-release/src/app/ParticleWorld.app/Contents/MacOS/ParticleWorld --gpu-test

Use windows-release on Windows. Restore the default with the same configure
command and -DPW_WORKGROUP_SIZE=128. Separate build directories may also be
used. CI declares both variants on both platforms; hosted compilation alone
does not certify device execution.

The same setting controls C++ ceiling dispatch counts, shader NUM_THREADS,
shader cache keys and manifests. The loader rejects compute manifests compiled
for the other size, including during live reload. Benchmark and soak reports
record workgroup_size. GPU suites cover 1, 127, 128, 129, 255, 256 and 257 slots;
pool and visibility suites additionally cover 16,384. Both variants passed the
CPU and Metal GPU suites locally; Windows/D3D11 execution remains unverified.
