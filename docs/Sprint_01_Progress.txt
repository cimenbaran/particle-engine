SPRINT 1 IMPLEMENTATION STATUS
Updated: 12 October 2026

Sprint 1 is in progress. This is a foundation implementation, not a claim that
the full particle core or either platform certification gate is complete.

Implemented and locally exercised
- C++20/CMake 3.28+ source layout, Ninja presets, fixed dependency commits and
  a local Git repository on codex/sprint-1-foundation.
- SDL3 native window lifecycle and a small native-handle adapter. bgfx owns
  the Metal layer; no second SDL Metal layer is created.
- Explicit Metal/D3D11 selection with backend fallback disabled. Compute,
  binding/instance limits and diagnostic image support are checked at runtime.
- Backend shaderc build rules and executable-relative assets. macOS assets
  are in bundle Resources, matching SDL_GetBasePath behavior.
- An ImGui SDL3 platform backend and project bgfx renderer with font texture,
  scissor, index offsets, framebuffer scaling and deferred resource destruction.
- GPU reset, ping-pong gravity/drag/analytic box contacts and instanced rendering
  of 16,384 seeded particles. Simulation views 0-4 and visibility view 5 precede diagnostic export/
  copy views 6-7 and draw views 10 and 20.
- A 64-byte particle ABI, 32-byte packed render record, stable ID/generation
  authoring fields, CPU command validation and fixed 1/60-second scheduling.
- Pause, single tick, seeded reset, orbit controls and CPU/GPU frame-time display.
- Tick-addressed command queue with stable sequences, 32 commands per tick,
  256 pending commands, a 120-tick horizon and aggregate spawn quotas.
- Live center-box impulse control publishes bounded velocity changes to GPU
  uniforms at the next tick, with spatial/material filters and queue diagnostics.
  Reset clears commands. Spawn/remove/impulse commands execute in submission
  order before integration; heat and terrain commands are not connected.
- GPU active/free slot classification, atomic spawn reservations, alive flags,
  generation increments on reuse and lifetime expiry. Empty-scene, spawn and
  remove controls are connected. Fixed-capacity draws explicitly mask dead slots.
- Versioned material JSON validation, seven profiles, portable packed asset
  output and schema/content fingerprints. GPU material properties drive drag,
  friction, restitution and color; density determines reset-time particle mass.
- Solid-material scene selection and tick-boundary material reload retain the
  previous valid table on errors and reject incompatible live-material edits.
- Delayed GPU active/free/rejected-spawn statistics use a three-slot, 16-byte
  readback ring per counter source (pool and visibility). Scene epochs discard
  stale results; normal operation never
  waits for the ring. Diagnostics do not control simulation or draw counts.
- GPU sphere/frustum culling, visible-record compaction and GPU-written indexed
  indirect drawing. The optional fixed-capacity fallback masks its cleared tail.
  Camera movement while paused rebuilds visibility without advancing simulation.
- Configurable capacity through 1,048,576 and a fixed 1080p offscreen benchmark
  with warmup, frame-ID-matched GPU timing, completion-based throughput, JSON/CSV
  output, input/build provenance and final count/image checks.
- GPU whole-pool ownership, finite-state and identity audits with latched
  failures, fault-injection tests and a wall-clock soak mode. The stress loop
  exercises full/empty pools, duplicate removal, reuse, expiry, impulses and
  intentional CPU quota rejection. Only compact summaries return to the CPU.
- CPU invariant/material tests, real-device GPU ABI tests and bounded runs.
- A Windows/macOS CI workflow for builds, shaders, CPU tests and artifacts.
  The workflow is authored locally; it has not run on a remote CI service.

Verified evidence
- Local machine: Apple M3 Max, 48 GB unified memory. This is not the design's
  M1 Pro reference tier, and these checks are not performance certification.
- Release configuration and compilation completed with AppleClang 21 and Metal.
- CTest core_invariants passed in CPU-only and full application builds.
- Full-build material_validation passed schema, portable binary and reload
  compatibility checks. Metal round-tripped all seven 64-byte material records.
- GPU render records matched positions, packed colors, classes, stable IDs and
  flags after integration at counts 1, 127, 128 and 129.
- Native UI verification: Sand selection reset to tick 0; a queued color edit
  remained unapplied while paused, then appeared on single tick. Malformed JSON
  displayed an error while retaining the working table; restoring JSON reloaded
  successfully. Fluid, gas and thermal behavior are not implemented.
- --gpu-test passed exact 64-byte round trips for counts 1, 127, 128 and 129
  through GPU reset and export passes. This verifies ABI and ordered compute
  visibility; it does not certify a free list or the future granular solver.
- --frames 600 completed and shut down cleanly after 302 fixed ticks.
- The final GPU suite additionally passed gravity, drag, floor/box contacts,
  finite-state and identity preservation against a CPU reference at all four
  particle counts (relative/absolute float tolerance 1e-5).
- Core queue tests passed ordering across ticks, stale/future rejection, sequence
  stability, per-tick/full-queue/spawn quotas, parameter limits and reset.
- GPU pool tests passed at capacities 1, 127, 128, 129 and 16,384: empty/full
  pools, zero/excess spawns, exact active/free ownership, duplicate removals,
  generation reuse, lifetime expiry and masked dead render records.
- Ordered pool brush dispatches passed exact velocity checks after 1 and 32
  impulses, including material and spatial misses. Generation wrap is rejected.
- Native pool UI: empty at tick 0; 1,024 particles spawned on tick 1, removed
  on tick 2, and spawned again into freed slots on tick 3.
