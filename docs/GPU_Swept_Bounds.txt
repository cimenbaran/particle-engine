GPU SWEPT BOUNDARIES

Scope
GpuSweptBounds performs constant-velocity sphere sweeps inside six analytic
boundary planes, optionally around one fixed interior sphere, and caps incoming speed. GPU tests and optional interactive
granular mode use it. GpuGranularStep supplies forces, contacts and lifetime
evolution; the standalone sweep only changes dynamic-solid pose and velocity.
Swept_Bounds_Reference.txt defines the independent CPU oracle and substep plan.

Input profile
Immutable ParticleGpu input, material table and upstream error status. Capacity
0..1,048,576. dt is a positive normal float <=1 second. Speed limit is finite in
[0.001,1,000,000] m/s (default 12); bounce threshold is finite and nonnegative
(default 0.5); event budget is 1..1024 (default 16). Material count is 1..65536.
Bodies must be alive solids with slot identity matching storage, positive
generation, radius 0.0625, finite pose/velocity and zero or positive normal finite
inverse mass. Material friction/restitution must be in [0,1], including rejection
of negative subnormal coefficients. Dead slots are skipped before material access;
liquid/gas and valid static solids preserve their complete records. Static poses
may lie outside the domain because they are not advanced.

Dynamic centres must start within [-7.9375,7.9375] x [0.0625,15.9375] x
[-7.9375,7.9375]. Invalid initial overlap/outside state is a visible error rather
than an implicit teleport. The ceiling is part of this bounded granular profile;
recordings/UI must distinguish it from the current open-top ballistic model.

Sweep and speed limit
Normalize velocity using a scaled vector, avoiding overflowing its squared length
or dividing directly by FLT_MAX on Metal. If speed exceeds the limit, rescale it
with a four-float-epsilon margin and count the capped body. Reflecting and friction
responses cannot increase speed. The final position is the result of consuming
remaining time after each impact, rather than clamping the original endpoint.

Find the earliest of three per-axis plane times. Equal float times resolve
simultaneous normals together; friction acts in the common tangent space using
the combined normal impulse magnitude. Low-speed normal impacts resolve to zero.
The CPU oracle uses double arithmetic, so extremely close impacts may group
differently within float rounding; agreement tests use explicit tolerances.
Starting on a plane and moving outward is a zero-time event; grazing/inward
motion is not a collision. A final clamp removes endpoint rounding at the planes.

Publication and diagnostics
A sequential view clears status, computes candidates and atomically aggregates
errors, then publishes in a separate apply dispatch. Any error copies the entire
original pool unchanged. Upstream failure blocks processing. Input is immutable.
Status: [error bits, proposed capped bodies, completed-body collision events,
completed-body incident planes]. Metrics describe candidate work and must not be
interpreted as committed changes when error bits are nonzero.
Error bits: 1 upstream, 2 invalid state/material/profile, 4 event budget exhausted,
8 nonfinite result. Exhaustion does not silently discard remaining travel.

Two outputs alternate to avoid input/output aliasing; scratch candidate storage
is separate. Payload is 192 bytes per slot plus 16-byte status (minimum one slot
allocated at capacity zero). No allocation/readback during submit. At most five
compute bindings. Uses the existing velocity clear/apply shaders; invalid handles,
scratch/material aliases and the component's own status as upstream are rejected.
A caller performing repeated steps must retain/aggregate errors separately before
clearing this component's status on a later submission.

Validation
The original 45 enclosure fixtures pass at both Metal workgroup sizes: CPU trajectory comparisons across
workgroup boundaries; nine restitution/friction combinations on 257 seeded bodies;
analytic floor/endpoint/grazing/corner cases; speed caps including FLT_MAX input;
static/phase/dead exclusions; invalid identity/radius/mass/material/nonfinite data;
upstream failure, exhaustion, whole-pool rollback and bad-then-valid reuse.
Input/persistent fields and excluded/failed state are compared exactly. Position
error limit is 2e-4 m; velocity limit is 2e-4 * max(1, abs(expected)). Tests also
check strict geometric containment, diagnostics and energy/cap bounds.
See tests/results/m3-max-swept-bounds.txt for local evidence. D3D11 is pending.

Current integration
GpuGranularStep composes forces, sweeps, bounded contact corrections, velocity
reconstruction/response and whole-tick publication. Interactive granular mode
uses this chain and displays delayed cap/error diagnostics. Its final stage
constrains boundary velocity after corrections. See GPU_Granular_Step.txt.
The planner's half-feature travel guarantee is not a guarantee about position-
solver corrections. Cross-backend stability, sustained sphere-scene soaks and
reference-hardware performance remain separate gates.

Optional interior sphere (component API)
submit accepts an AnalyticSphere after the event budget. Radius zero disables
it, preserving the existing live profile. Enabled radii are 0.0625..4 metres;
centre coordinates must be finite. The expanded sphere plus a 0.125 m clearance
must fit inside the inset enclosure, so simultaneous sphere/plane contacts cannot
occur in the supported profile. This is one fixed sphere using the moving body's
friction and restitution. No particle-sized allocations or extra compute bindings
are added; a vec4 uniform supplies the collider.

Each event chooses the earlier of the six-plane impact and the sphere entry.
Remaining time is retained, so sphere-then-wall and wall-then-sphere paths work in
one submission. Exact plane ties still use the existing common-tangent response.
Sphere response removes only bounded tangential speed and applies the same bounce
threshold. Total incident-normal diagnostics count both wall planes and sphere
hits. Budget exhaustion still rolls back the whole pool, including earlier impacts.
Initial overlap of a participating dynamic body reports state error 2. Existing
static/dead/excluded preservation rules remain; this is not overlap recovery.

Entry uses geometric chord construction and a stable near-surface root. If GPU
division places a computed entry just beyond dt but the segment endpoint lies
inside the expanded sphere, that endpoint independently proves the collision and
retains it at dt. A 0.000002 m outward guard at sphere impacts avoids repeated
zero-time re-entry caused by a rounded surface position. The existing 0.0002 m
position comparison tolerance was not widened. This guard is numerical separation,
not a scene-scale collider inflation or general contact-skin policy.

The initial 87-case sphere suite included the prior 45 enclosure cases plus sphere workgroup
boundaries, nine restitution/friction combinations, six approach and endpoint
directions, grazing/miss/slow contact, a 10000 m/s shot, both sphere/wall event
orders, exhaustion, initial-overlap rollback, reuse, exclusions and upstream faults.
Pure sphere trajectories compare with the independent double oracle; mixed paths
use analytic one-dimensional distances. Original buffers and persistent fields
remain bitwise unchanged. Both Metal workgroup suites pass; Windows is unverified.

The live granular coordinator and settling tracker receive scene.obstacle.
Sphere_Terrain.txt describes the native preset, shared geometry, reset/spawn
contracts and renderer. Ordinary presets retain the disabled default. Interior
sphere correction, coordinator, settling and application fixtures pass on Metal;
Windows coverage must pass the sweep gate before validating these later stages.
Granular recording/replay and collision-normal visualization remain open.

Sphere normalization refinement
The shared sphere entry helper refines reciprocal-square-root estimates with one
Newton step before constructing the ray direction and contact normal. This is a
candidate for the D3D11 WARP oblique-friction discrepancy recorded in
../tests/results/ci-38326929216-sphere-sweep.txt; new Windows execution is required.
The GPU sweep suite now has 129 fixtures. Forty-two added cases rotate a half-radius
miss across signed axes and all eight octants, with friction 0.49, 0.5 and 0.57.
Position and velocity tolerances are unchanged; the double CPU sweep is the oracle.
