SPRINT 3 - RESIDENT WORLD, DESTRUCTION AND PERSISTENCE

Goal: Turn terrain into debris and settled particles back into terrain safely.
Planning window: Weeks 7-8.
Dependencies: Sprint 2 granular and spatial-index gates.
Source: Particle_World_Design.docx, sections 2, 6, 8 and 10-13.

Preparation status
CPU chunk/voxel addressing and a checked resident layout are implemented and
covered by exhaustive local-index, signed-boundary, extreme-value and origin
round-trip tests; see ../docs/Voxel_Coordinates.txt. Sparse CPU material occupancy
now allocates nonempty chunks and tracks monotonic content/surface revisions,
including face-neighbor invalidation and stale-edit rejection. Atomic CPU batches
now stage all changes before a single revision commit; allocation failure tests
verify there are no partial occupancy edits. Immutable terrain publications now stage an independent CPU copy, occupancy
and mesh, then require an asynchronous GPU upload acknowledgement before
replacement; obsolete competing edits cannot overwrite newer publications.
See ../docs/GPU_Terrain_Publication.txt. GPU debris capacity reservation now
prepares deterministic all-or-nothing claims in a private particle snapshot
(../docs/GPU_Debris_Reservation.txt). Private debris activation now validates
claims/generations and initializes whole batches without modifying live input
(../docs/GPU_Debris_Activation.txt). A private GPU clearance gate now checks new
grains against candidate terrain, existing solids and other new grains
(../docs/GPU_Debris_Clearance.txt). A frozen-pool coordinator now validates the
base tick, owner and material epoch, waits for terrain/particle acknowledgements,
and jointly adopts terrain, particles and per-material conversion totals
(../docs/GPU_Debris_Transaction.txt). A bounded interactive excavation brush now
plans local debris sites and commits up to 32 voxels per click, with conversion
totals and material-targeted particle controls (../docs/Terrain_Excavation.txt).
A typed explosion planner now computes radial falloff, calibrated resistance,
conservative fracture/kinetic budgets and complete locally placed debris batches
(../docs/Terrain_Explosion.txt). Live controls now schedule acknowledged batches,
charge only successful commits and defer under capacity/clearance pressure
(../docs/Staged_Explosion.txt). Existing-particle blast impulse budgeting,
cosmetic blast quotas and persisted material resistance remain open.
Pure mass plans choose
nearest product counts with explicit signed per-material quantization capped at
5% (../docs/Terrain_Mass_Quantization.txt); committed debris conversion totals
are tracked per material. Deposition and whole-world mass inventory remain open. CPU exposed-face
extraction now handles chunk seams, deterministic material-tagged quads and
revision validation. See ../docs/Sparse_Voxel_Storage.txt and
../docs/Voxel_Surface.txt. A double sphere-versus-single-voxel reference now
covers faces, rounded edges/corners and closed-segment endpoints against an
independent distance-search oracle; see ../docs/Swept_Voxel_Reference.txt.
An independent GPU single-voxel query now compares against that CPU reference;
see ../docs/GPU_Voxel_Sweep.txt. Immutable resident GPU occupancy snapshots now
feed short swept queries over all candidate occupied voxels, with stale-source
and shared-origin rejection; see ../docs/GPU_Resident_Voxels.txt. These queries
now feed GpuVoxelMotion and optional live collision probes with gravity, drag,
material response and whole-tick rollback. See ../docs/GPU_Voxel_Motion.txt.
The optional basin-sized sparse index and pair primitives now cover the full
32x16x32-metre basin; see ../docs/GPU_Basin_Grid.txt. Pair corrections can now
sweep current voxel occupancy before whole-iteration commit; see
../docs/GPU_Voxel_Contacts.txt. A terrain velocity finishing pass now removes newly inward motion and applies
material friction after pair response; see ../docs/GPU_Voxel_Finish.txt. Static
traction now resists supported position corrections (GPU_Voxel_Traction.txt).
Settling checks current voxel faces/edges/corners
and reports live basin candidates with hysteresis and physics-fault invalidation.
Candidates remain active; deposition remains pending. An optional pool spawn
path now checks current voxel occupancy before reserving slots; the live basin now exposes an active command pool (../docs/GPU_Basin_Pool.txt). Optional
lattice brushes now space candidates within a command, and a fresh sparse-index
query excludes existing particles across commands (../docs/GPU_Spawn_Clearance.txt).
Live basin spawning, removal, impulses and clear now use a 1,024-slot GPU pool. The complete particle/terrain tick
now powers Drop interacting diagnostics in the basin preview, with whole-tick rollback;
see ../docs/GPU_Basin_Tick.txt.
A deterministic full basin recipe
and exposed-surface GPU renderer now run in --terrain-preview, including seed
rebuilds and matching render/occupancy revision checks. See
../docs/Resident_Basin.txt. Thermal simulation, save files and tick-boundary
origin publication are not connected. Dirty chunk mesh reuse, existing-particle blast impulses
and deposition remain open. Development prioritizes macOS.

Tasks
[ ] S3-01 Implement sparse 32x32x32 voxel chunks at 0.125-metre spacing,
    material occupancy, persistent edits and thermal detail for active regions.
    Build the fully resident 32x16x32-metre basin with ledge and sand slope.
[ ] S3-02 Introduce integer chunk coordinates, local positions and explicit
    CPU/GPU revisions. Commit shared origin rebases at tick boundaries and
    define out-of-region behavior; camera culling must never suspend physics.
[ ] S3-03 Render exposed terrain surfaces and dirty neighboring caches after
    edits. Publish occupancy, collision and rendering revisions consistently.
[ ] S3-04 Replace analytic-only terrain contact with swept sphere-versus-voxel
    collision. Edited regions must query current occupancy immediately; any
    optional cached collider remains invalid until its revision is current.
[ ] S3-05 Route terrain editing and explosions through validated commands.
    Calculate affected resident chunks, distance falloff, resistance, bounded
    energy, removal proposals and required physical debris capacity.
[ ] S3-06 Reserve debris slots before committing removals. Stage oversized
    blasts over ticks while retaining unconverted voxels. Commit occupancy,
    collision revisions and debris activation together; apply bounded impulses
    to existing particles and separate cosmetic dust/spark quotas.
[ ] S3-07 Implement deterministic deposit claims into empty voxels. Commit
    occupancy first and retire only acknowledged particles; failed claims
    remain dynamic. Track material mass with explicit quantization tolerance.
[ ] S3-08 Wake nearby matter from edits, impacts and heat within bounded budgets.
    Document static disconnected overhangs; defer structural collapse/fracture.
[ ] S3-09 Implement versioned snapshots containing seed, material hash, chunk
    edits, simulation profile and optional active particles. Pause at a tick
    boundary, stage asynchronous readback and serialize via temporary file
    plus atomic replacement, respecting authoritative-state acknowledgements.
[ ] S3-10 Validate save counts, bounds, schema migration and material references
    before allocation. Add load/reset controls and seed-plus-command presets;
    describe their cross-GPU replay limits without promising identical motion.
[ ] S3-11 Add diagnostics for terrain/debris mass, pending transactions, rejected
    edits and cache revisions, plus delayed selection using ID and generation.

Validation and completion gates
[ ] Test chunk indexing, negative coordinates, rebasing, border edits and
    immediate collision after edits; no stale collision revision is accepted.
[ ] Exercise simultaneous deposit claims, full pools, oversized blasts,
    repeated explosions and failed deposits without duplicate or lost matter.
[ ] Account for all physical conversion mass within documented voxel tolerance;
    full capacity must defer conversion rather than silently delete material.
[ ] Round-trip modified scenes and active snapshots; reject corrupt or
    unsupported files without partially adopting invalid live state.
[ ] Run ten-minute edit/explosion/deposition soaks on both backends and record
    frame times, transaction limits and memory growth.

Handoff: Editable resident terrain, mass-accounted destruction/deposition,
safe snapshot persistence and a basin ready for water and reactions.
